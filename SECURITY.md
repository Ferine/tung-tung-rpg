# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| 0.001 | Yes |

Security fixes are made on the default branch and included in subsequent
releases.

## Reporting a vulnerability

Do not open a public issue containing exploit details, malicious files, or a
proof of concept. Use GitHub's private vulnerability reporting from the
repository's **Security** tab. If private reporting has not been enabled, open
a public issue asking the maintainer to establish a private contact channel,
without including sensitive details.

Include the affected revision, impact, reproduction conditions, and the
smallest safe proof needed to validate the report. Reports about the Python
asset pipeline and libretro test harness are in scope as well as ROM behavior.
